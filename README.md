# ScreenFix

Маленькая программа для Windows. Вы выделяете русский текст в любом окне, нажимаете горячую клавишу — локальная модель из LM Studio исправляет орфографию, пунктуацию и грамматику **по правилам вашей площадки**. Рядом с курсором появляется окно с результатом, исправленный текст уже лежит в буфере обмена.

Если текст нельзя выделить (картинка, видео, удалённый рабочий стол), второй режим читает область экрана встроенным распознаванием Windows (OCR) и исправляет прочитанное.

Всё работает на вашем компьютере: текст уходит только в LM Studio по адресу `http://localhost:1234`.

## Что нужно

- Windows 10 или 11.
- LM Studio с загруженной моделью для чата и включённым сервером (вкладка **Developer** → **Start Server**).
- Для режима «область экрана»: в Windows должен стоять русский язык с распознаванием текста (Параметры → Время и язык → Язык и регион).

## Как получить программу (.exe)

Программа собирается на GitHub автоматически.

1. Создайте новый репозиторий на GitHub (лучше **Private**).
2. **Add file → Upload files**: перетащите всё содержимое этой папки, кроме папки `.github` (веб-загрузка GitHub её пропускает). Нажмите **Commit changes**.
3. **Add file → Create new file**, имя файла: `.github/workflows/screenfix-build.yml`. Вставьте текст из файла `.github/workflows/screenfix-build.yml` этой папки и нажмите **Commit changes**.
4. Вкладка **Actions** → **ScreenFix build** → **Run workflow**. Обычно через несколько минут сборка станет зелёной.
5. Откройте запуск, внизу в разделе **Artifacts** скачайте `ScreenFix-windows`, распакуйте в любую папку (например, `C:\ScreenFix`).

В отчёте сборки есть блок **Self-test of the built exe**: это проверка собранной программы на чистом Windows.

## Первый запуск

1. Запустите LM Studio, загрузите модель, включите сервер.
2. Запустите `ScreenFix.exe`. Откроется небольшое окно: сверху список горячих клавиш, ниже — состояние LM Studio. Крестик сворачивает окно, программа остаётся работать. Полностью закрыть: кнопка **Выход** или `Ctrl+Alt+Q`.
3. Нажмите **Самопроверка**. Отчёт покажет, что работает именно у вас: связь с LM Studio, скорость ответа модели на короткой фразе, буфер обмена, копирование выделенного (Ctrl+C), чтение текста с экрана. Горячие клавиши проверяются при запуске: если одна из них занята другой программой, ScreenFix скажет, какая.
4. Откройте **Правила** (файл `rules.txt`) и вставьте правила вашей площадки. Строки, начинающиеся с `#`, программа не читает. Пока там пусто, текст исправляется по общим нормам русского языка, а не по правилам площадки.
5. Windows может показать «Система Windows защитила ваш компьютер» (программа не подписана): **Подробнее → Выполнить в любом случае**. Антивирус иногда ложно ругается на программы, собранные PyInstaller.

## Как пользоваться

| Клавиши | Что делает |
|---|---|
| `Ctrl+Alt+K` | Исправить выделенный текст. Программа сама нажимает Ctrl+C, отправляет текст модели и показывает результат. |
| `Ctrl+Alt+V` | Вставить исправленный текст на место выделенного (программа нажимает Ctrl+V). |
| `Ctrl+Alt+O` | Режим «область экрана»: экран замирает, протяните рамку вокруг текста, он будет прочитан и исправлен. Esc или правая кнопка мыши — отмена. |
| `Ctrl+Alt+Q` | Выйти из программы. |

В окне результата зелёным подсвечено добавленное, красным зачёркнуто удалённое. Кнопка **Правки** включает и выключает подсветку, **Копировать** кладёт текст в буфер, **Вставить на место** делает то же, что `Ctrl+Alt+V`. Окно не забирает фокус у вашей программы, поэтому выделение остаётся на месте.

Привычный порядок работы: выделить текст → `Ctrl+Alt+K` → посмотреть правки → `Ctrl+Alt+V`.

## Настройки (`config.json`, лежит рядом с программой)

Файл создаётся при первом запуске. Менять можно в Блокноте. Правила и настройки подхватываются при следующем исправлении, **горячие клавиши — после перезапуска программы**.

| Поле | Значение по умолчанию | Зачем |
|---|---|---|
| `base_url` | `http://localhost:1234/v1` | Адрес сервера LM Studio. |
| `model` | пусто | Имя модели. Пусто — первая модель для чата из списка LM Studio. |
| `temperature` | `0.1` | Чем ниже, тем меньше «творчества» у модели. |
| `max_tokens` | `2048` | Предел длины ответа. |
| `timeout_s` | `120` | Сколько секунд ждать очередную порцию ответа. |
| `stream` | `true` | Показывать ответ по мере появления. |
| `auto_copy` | `true` | Сразу класть результат в буфер. Если `false`, буфер возвращается к прежнему тексту. |
| `max_input_chars` | `8000` | Длиннее этого текст не принимается (защита от случайного выделения всего документа). |
| `hotkey_fix`, `hotkey_ocr`, `hotkey_paste`, `hotkey_quit` | см. таблицу выше | Формат: `ctrl+alt+k`, допускаются ctrl, alt, shift, win и латинская буква, цифра, F1–F12. Раскладка значения не имеет. |
| `ocr_language` | `ru` | Язык распознавания. |
| `extra_body` | `{}` | Дополнительные поля запроса для опытных пользователей. |
| `log_text` | `false` | Писать ли сам текст в `screenfix.log`. По умолчанию в журнале только время, размеры и скорость. |

## Что важно знать

- **Проверяйте результат глазами.** Модель на 7–8 миллиардов параметров иногда «исправляет» лишнее или пропускает ошибки. Подсветка правок как раз для этого.
- **Режим выделения точнее режима экрана.** Распознавание текста с картинки может исказить буквы, поэтому для точной вычитки лучше выделять и копировать, а область экрана брать, когда иначе нельзя.
- **Программы «от имени администратора».** Если нужная программа запущена с повышенными правами, а ScreenFix нет, Windows не пропустит нажатие Ctrl+C. Запускайте ScreenFix так же, как нужную программу.
- **Буфер обмена.** Программа временно использует его для копирования. Если включена история буфера (`Win+V`), в ней останется скопированный текст.
- **Скорость.** Модели с режимом «размышлений» (например, Qwen3) тратят время на рассуждения, которые ScreenFix вырезает из ответа. Самопроверка показывает время ответа на короткой фразе. Если оно заметно больше пары секунд, попробуйте модель без размышлений.
- **Горячая клавиша занята.** Тогда программа при запуске скажет, какая именно. Поменяйте её в `config.json`.
- Если в какой-то программе при срабатывании горячей клавиши открывается меню, смените клавишу на сочетание без Alt, например `ctrl+shift+k`.

## Если что-то не работает

| Сообщение | Что делать |
|---|---|
| «Не удалось связаться с LM Studio» | Запущен ли LM Studio, включён ли сервер (Developer → Start Server), загружена ли модель. |
| «Не получилось скопировать выделенный текст» | Выделен ли текст; запущена ли та программа от администратора; не запрещает ли она копирование. Используйте режим экрана. |
| «В Windows нет распознавания текста для языка…» | Добавьте русский язык в Параметрах Windows (оставьте галочку про распознавание текста) или используйте режим выделения. |
| «Модель вернула пустой ответ» | Модель потратила весь `max_tokens` на рассуждения. Возьмите модель без размышлений или увеличьте `max_tokens`. |
| «Файл rules.txt не читается (нужна кодировка UTF-8)» | В Блокноте: Файл → Сохранить как → Кодировка: UTF-8. |

Рядом с программой лежат `screenfix.log` (журнал без текста), `selftest.txt` (последняя самопроверка) и, при сбое на старте, `screenfix_crash.log`.

Автозапуск с Windows: `Win+R` → `shell:startup` → положите туда ярлык на `ScreenFix.exe`.

## Что проверено автоматически, а что нет

Проверено тестами (в том числе на сборке с настоящим Tk): запросы к LM Studio со стримингом и ошибками (на заглушке сервера), вырезание «рассуждений» модели, чтение правил и настроек, подсветка правок, порядок действий при горячих клавишах, отмена, возврат буфера, окна результата и выбор области, обмен с PowerShell для распознавания.

**Не проверялось без Windows и вашей конфигурации:** реальные вызовы WinAPI (горячие клавиши, буфер, нажатие Ctrl+C), сценарий распознавания текста Windows, внешний вид в вашем масштабе экрана, работа с вашей площадкой и моделью. Это показывает `Самопроверка` и ваш первый запуск.

## Запуск из исходников

```
pip install -r requirements.txt
python run.py
python run.py --selftest      # проверка из командной строки
python -m unittest discover -s tests
```

Правила вашей площадки и условия работы с ней — ваша зона ответственности: перед использованием убедитесь, что площадка и заказчик допускают сторонние программы и обработку текста моделью, особенно если действует соглашение о неразглашении.
